fix(serving): accept HTTP-shaped backend options

Two bugs that only the gateway tests could catch, found by reviewing them
before CI ran them for the first time:

- POST /v1/models/load sends `backend_options` as JSON, so `config` arrives as a
  dict. NumpyTransformerBackend read `config.vocab_size` straight off it and
  raised AttributeError. It now coerces a Mapping into TransformerConfig, which
  also makes the documented HTTP payload actually usable.
- The documented vLLM options are camelCase (`baseUrl`), which never matched the
  constructor's `base_url`. build_backend now normalises option keys to
  snake_case and raises a ValueError naming the accepted options instead of
  letting a bare TypeError escape as a 500.

Adds three tests that run without FastAPI, so this path is covered locally too.
96 tests pass; ruff clean.
